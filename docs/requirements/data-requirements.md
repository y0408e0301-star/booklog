本書は要件定義書の一部である。承認は[要件定義書](requirements.md)で一括して行い、変更は要件定義書 16 章の手続きで行う。

本書では、利用者から見てアプリがどんなデータを扱うかを定める。

---

## 1. ユーザー

| 項目 | 型 | 必須 | 条件 |
| --- | --- | --- | --- |
| ID | 数値 | ○ | アプリが自動で付ける。重複しない。画面には出さない |
| ユーザー ID | 文字列 | ○ | トリム後 3〜15 文字の半角英数字と「_」。大文字・小文字を区別せずに重複しない。変更できない |
| 表示名 | 文字列 | ○ | トリム後 1〜30 文字 |
| パスワード | 文字列 | ○ | 8〜64 文字の半角文字、英字と数字を両方含む。元に戻せない形で保存する（要件定義書 N-14） |
| 自己紹介 | 文字列 | | 0〜160 文字。改行を含められる |
| ログインの失敗回数 | 数値 | ○ | 続けて失敗した回数 |
| ログインできない期限 | 日時 | | 5 回続けて失敗したときの 15 分後（要件定義書 N-15） |
| 登録日時 | 日時 | ○ | 自動で記録 |
| 更新日時 | 日時 | ○ | 自動で記録 |

## 2. 本

Google Books API から取った本の情報である（要件定義書 P-3・P-4）。書籍検索の結果のうち、利用者が選んだ本だけを保存する。

| 項目 | 型 | 必須 | 条件 |
| --- | --- | --- | --- |
| ID | 数値 | ○ | アプリが自動で付ける。本のページの URL に使う |
| Google Books の ID | 文字列 | ○ | Google Books API が本ごとに付けている ID。重複しない（同じ本を 1 つにまとめる） |
| ISBN | 文字列 | | 13 桁の数字。API が 10 桁だけを返したときは 13 桁に直す。ない本もある |
| 書名 | 文字列 | ○ | サブタイトルがあれば書名の後ろに続けて持つ |
| 著者 | 文字列の並び | | 複数のときは API が返した順。ない本もある |
| 出版社 | 文字列 | | |
| 出版日 | 文字列 | | API が返したまま（「2024」「2024-05」「2024-05-10」のどれか） |
| 紹介文 | 文字列 | | API が返したまま。HTML のタグは取り除いて文字だけを持つ |
| 表紙の URL | 文字列 | | Google Books の表紙の画像の URL。https にそろえる。画像そのものは保存しない |
| 保存日時 | 日時 | ○ | 自動で記録 |

本は、レビュー・読書ステータスがなくなっても消さない。

## 3. レビュー

| 項目 | 型 | 必須 | 条件 |
| --- | --- | --- | --- |
| ID | 数値 | ○ | アプリが自動で付ける。重複しない。新しいレビューほど大きい |
| 書いた人 | ユーザー | ○ | |
| 本 | 本 | ○ | 書いた人と本の組み合わせは重複しない（1 人 1 冊 1 つ） |
| 星 | 数値 | ○ | 1〜5 の整数 |
| 感想 | 文字列 | ○ | トリム後 1〜2,000 文字。改行を含められる |
| 投稿日時 | 日時 | ○ | 自動で記録。タイムラインの並び順に使う |
| 編集日時 | 日時 | | 最後に編集した日時。編集していないレビューにはない |

## 4. 写真

| 項目 | 型 | 必須 | 条件 |
| --- | --- | --- | --- |
| ID | 数値 | ○ | アプリが自動で付ける |
| レビュー | レビュー | ○ | 写真を添えたレビュー |
| 置き場所 | 文字列 | ○ | S3 の中での場所（キー）。重複しない。元のファイル名は使わない |
| 形式 | 文字列 | ○ | JPEG・PNG・WebP のどれか |
| 大きさ | 数値 | ○ | バイト数。5MB（5,242,880 バイト）以下 |
| 並び順 | 数値 | ○ | 0〜3 |

写真のファイルそのものは S3 に置き、データベースには上の項目だけを持つ（要件定義書 P-2）。

## 8. 読書ステータス

本棚に入っている 1 冊を表す。

| 項目 | 型 | 必須 | 条件 |
| --- | --- | --- | --- |
| ユーザー | ユーザー | ○ | |
| 本 | 本 | ○ | ユーザーと本の組み合わせは重複しない |
| ステータス | 文字列 | ○ | 「読みたい」「読書中」「読了」のどれか |
| 更新日時 | 日時 | ○ | 自動で記録。本棚の並び順（新しい順）に使う |

ステータスを外すと、本棚からその本がなくなる。レビューを書いたときに本棚にない本は「読了」で入れる（FN-03）。すでに本棚にある本のステータスは変えない。

## 9. リフレッシュトークン

ログインしたままにするために、ログインした人に渡す文字列である。JWT（要件定義書 N-19）の有効期限が切れたときに、これを使って新しい JWT を受け取る。

| 項目 | 型 | 必須 | 条件 |
| --- | --- | --- | --- |
| ユーザー | ユーザー | ○ | ログインした人。1 人が複数のブラウザでログインしたときは、ブラウザごとに 1 つ持つ |
| トークン | 文字列 | ○ | 推測できない長い文字列。データベースには元に戻せない形（ハッシュ）で保存する |
| 有効期限 | 日時 | ○ | 発行してから 14 日後 |
| 無効にした日時 | 日時 | | 使って新しいものに替えたとき、ログアウトしたときに記録する |
| 発行日時 | 日時 | ○ | 自動で記録 |

有効期限を過ぎたものは、1 日 1 回まとめて消す。

## 10. 上限

| 対象 | 上限 |
| --- | --- |
| 感想 | 2,000 文字 |
| コメントの本文 | 500 文字 |
| 1 つのレビューの写真 | 4 枚 |
| 写真 1 枚の大きさ | 5MB |
| 自己紹介 | 160 文字 |
| 書籍検索の文字 | 100 文字 |
| ユーザー・本・レビュー・コメント・参考になった・フォロー・読書ステータスの件数 | 上限なし（性能の目標は要件定義書 N-1〜N-6 の条件で確かめる） |

## 11. 詳細

データの詳しい構造（ER 図）はデータ設計書で定める。

## 12. 保存する個人情報

ユーザー ID・表示名・自己紹介と、元に戻せない形にしたパスワードのみを保存する。メールアドレス・本名・電話番号は保存しない。レビュー・写真・コメント・本棚は利用者が自分で公開するものとして扱い、ログインした全員に見える（要件定義書 3.1）。
