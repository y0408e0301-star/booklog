## 1. 概要

### 1.1 背景

本アプリは学習課題として作成する。作成を通して、次の 4 つを習得する。

- ユーザー認証（登録・ログイン・ログアウト）
- データの作成・表示・更新・削除（CRUD）
- データどうしの関係（リレーション）：レビューと本、いいね・コメント・フォロー
- 画像のアップロードと保存（AWS S3）

あわせて、外部の API（書籍の情報）を使う方法と、AWS で公開する方法を身につける。技術は前に作った Raise timeline と同じもの（Spring Boot・React・PostgreSQL）を使う。

紙のメモや表計算ソフトで読書の記録をつけると、次の点で不便である。

- 書名・著者を毎回手で書く必要があり、表紙の画像もない
- 「いま読んでいる本」「読み終えた本」が分けにくい
- 感想を知り合いと共有したり、同じ本を読んだ人の感想を読んだりできない

### 1.2 目的

1. ISBN か書名で本を探して選ぶだけで、書名・著者・表紙が入った読書の記録を残せるようにする
2. 読んだ本に星（1〜5）と感想と写真でレビューを書き、フォローした人や同じ本を読んだ人と共有できるようにする
3. 本ごとに「読みたい」「読書中」「読了」を付け、自分の本棚として見られるようにする
4. ほかの人のレビューに「参考になった」とコメントで反応できるようにする

## 4. 前提条件・制約

| ID | 内容 |
| --- | --- |
| P-1 | データはリレーショナルデータベース（PostgreSQL）に保存する。開発中は Docker、公開時は AWS RDS で動かす。バージョンなどは技術スタック定義書に記録する |
| P-2 | レビューの写真は AWS S3 に保存し、データベースには置き場所だけを持つ。開発中は S3 の開発用のバケットを使い、自動のテストでは S3 と同じ使い方ができる MinIO を Docker で動かす |
| P-3 | 本の情報（書名・著者・出版社・出版日・ISBN・表紙）は Google Books API から取る。API はサーバーから呼び、API キーはサーバーだけが持つ。1 日に呼べる回数には上限があり、本アプリでは 1 日 1,000 回とみなして設計する（U-2 で決めた）。表紙の画像は保存せず、Google Books が返した画像の URL をそのまま使う |
| P-4 | 一度選ばれた本の情報はデータベースに保存し、本のページ・レビュー・本棚ではデータベースの情報を出す。Google Books の側で情報が変わっても、保存した情報は変えない |
| P-5 | 公開する場合は AWS に、CloudFront（入口・HTTPS）・ロードバランサー（ALB）・API のコンテナ（ECS Fargate）・データベース（RDS）・S3（画面と写真）で構築する。画面は S3 に置いて CloudFront から配る。公開の URL は CloudFront のもの（https://〜.cloudfront.net）とし、独自ドメインは取らない。構成はインフラ設計書に書く |
| P-6 | AWS は有料のため、公開は検収のときだけ行い、使わない間は API のコンテナと ALB を消し、RDS を止める。検収が終わったら環境を消す |
| P-7 | 利用者が使える機能・画面の動きは本書に書いたものに限る。本書に書いていない動きは保証しない |
| P-8 | 公開後の稼働状況は、AWS と Google Books API の稼働状況に左右される（11.2 参照） |

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| ユーザー | アカウントを登録した人 |
| ユーザー ID | ログインとプロフィールの URL に使う、ほかと重ならない英数字の名前。画面では @ を付けて出す（例：@taro_y） |
| 表示名 | レビューやコメントに出す名前。ほかの人と同じでもよい（例：たろう） |
| 本 | Google Books API で見つけ、だれかがレビューか本棚に入れた書籍。同じ本は 1 つにまとめる |
| ISBN | 本ごとに付いている国際的な番号。10 桁と 13 桁がある。本アプリでは 13 桁で持つ |
| 書籍検索 | ISBN か書名（著者名も可）で、Google Books API から本を探すこと |
| レビュー | 本に付ける星（1〜5）と感想。写真を添えられる。1 人が 1 冊に書けるのは 1 つだけ |
| ネタバレあり | 本の結末や大事な展開に触れていることを示す、レビューの印。書いた人が付ける。付いたレビューは、感想・写真・コメントを伏せて出し、「ネタバレを表示」を押すと開く。星は伏せない |
| 退会 | 自分のアカウントをなくすこと。その人のレビュー・写真・コメント・参考になった・フォロー・本棚もすべて消え、元に戻せない |
| 星（評価） | 本への評価。1〜5 の整数で、5 がいちばん高い |
| 平均評価 | その本のレビューの星の平均。小数点以下 1 桁で出す |
| 写真 | レビューに添える画像（本を撮った写真など） |
| 参考になった | ほかの人のレビューへの評価の印。1 人 1 レビューに 1 つ。取り消せる。自分のレビューには付けられない |
| コメント | レビューに付ける文章の返信。コメントへのコメントはできない |
| フォロー | ほかのユーザーのレビューを「フォロー中」タブに出すための登録。相手の承認はいらない |
| フォロー中・フォロワー | 自分がフォローしている人／自分をフォローしている人 |
| 読書ステータス | 本ごとに付ける「読みたい」「読書中」「読了」のどれか |
| 本棚 | 自分が読書ステータスを付けた本の一覧。ステータスごとに分けて出す |
| タイムライン | レビューを新しい順に並べた一覧。「フォロー中」と「すべて」の 2 つのタブがある |
| 署名付き URL | 一定時間だけ使える、S3 の写真を表示するための URL。期限が切れると開けなくなる |
| JWT | ログインした人が誰かを表す、改ざんを見破れる署名つきの文字列（JSON Web Token）。本アプリでは、ログインの状態をサーバーに覚えさせずに、この文字列で確かめる |
| 確認ダイアログ | 操作を実行する前に「よろしいですか？」と確認する小さな画面 |
| トリム | 入力した文字の前後にある空白（半角・全角スペース、タブ、改行）を取り除くこと |
| 文字数 | Unicode の文字（コードポイント）の数。漢字・ひらがな・英数字は 1 文字。絵文字の一部（肌の色を変えたもの、国旗など）は、見た目は 1 文字でも 2 文字以上として数える |

## 6. 利用の流れ

1. ブラウザでアプリの URL を開く
2. 初めての場合は「アカウントを作る」からユーザー登録する。2 回目以降はユーザー ID とパスワードでログインする
3. タイムラインが表示される
4. ヘッダーの検索欄に ISBN か書名を入れて本を探し、本のページを開く
5. 本のページで読書ステータス（読みたい・読書中・読了）を付ける。付けた本は自分の本棚に入る
6. 読み終えたら、本のページの「レビューを書く」から星・感想・写真を入れて投稿する
7. タイムラインや本のページでほかの人のレビューを読み、「参考になった」を押したりコメントしたりする。気になる人はプロフィールの「フォローする」でフォローする
8. 共用のパソコンで使った場合は、最後にログアウトする
9. 使うのをやめるときは、プロフィールの編集画面から退会する

## 8. 機能一覧

| 機能 ID | 機能 | 概要 | 主な画面 |
| --- | --- | --- | --- |
| FN-01 | ユーザー登録・ログイン・退会 | ユーザー ID とパスワードで登録・ログイン・ログアウトする。ログインの状態は JWT で持つ（JWT 認証）。5 回続けて失敗したら 15 分間ログインできない。ログインしていないと何も使えない。パスワードを入れ直して退会でき、退会するとその人のデータ（本を除く）をすべて消す。退会した人のユーザー ID は、ほかの人が新しく使える | G-1、G-2、G-9、G-13 |

| FN-03 | レビュー | 本に星（1〜5、必須）と感想（2,000 文字まで）でレビューを書き、編集・削除する。1 人が 1 冊に書けるレビューは 1 つ。レビューを書いた本が本棚になければ「読了」で入れる。「ネタバレあり」の印を付けたレビューは、どの画面でも感想・写真・コメントを伏せて出し、押すと開く | G-6、G-7、G-12 |
| FN-04 | 写真 | レビューに 4 枚まで（1 枚 5MB まで）写真を添えて S3 に保存し、拡大して見る。編集のときに足す・外すことができる | G-6、G-7、G-11 |
| FN-05 | 参考になった | ほかの人のレビューに「参考になった」を付ける・取り消す（1 人 1 レビュー 1 つ）。件数は誰でも見られる | G-3、G-5、G-7 |
| FN-06 | コメント | レビューに 500 文字までのコメントを付け、自分のコメントを削除する。中身と件数は誰でも見られる | G-7、G-12 |
| FN-07 | フォロー | 承認なしでフォロー・解除する。フォロー中・フォロワーの一覧と件数は誰でも見られる | G-8、G-10 |
| FN-08 | 読書ステータス・本棚 | 本ごとに「読みたい」「読書中」「読了」を付ける・変える・外す。プロフィールでステータスごとの本棚として見せる | G-5、G-8 |
| FN-09 | タイムライン | 「フォロー中」（自分とフォローした人）と「すべて」（全員）のタブで、レビューを新しい順に 20 件ずつ出す | G-3 |
| FN-10 | 本のページ | 本の情報（表紙・書名・著者・出版社・出版日・ISBN・紹介文）、平均評価とレビューの件数、自分の読書ステータス、その本のレビューの一覧を出す | G-5 |
| FN-11 | プロフィール | ユーザーの情報、フォローボタン、その人のレビューの一覧と本棚を出す。自分の表示名と自己紹介を編集する | G-8、G-9 |

## 11. 非機能要件

### 11.1 性能

次の条件で測定する：ユーザー 1,000 人・本 5,000 冊・レビュー 1 万件・コメント 3 万件・参考になった 5 万件・読書ステータス 3 万件、測定するユーザーのフォロー 1,000 人、3.2 の対応環境、下り 10Mbps 以上・上り 30Mbps 以上の回線。同じ操作を繰り返し測り、P95（小さい順に並べて 95% の位置の値）が目標値以内なら合格とする。合否は公開先（AWS）で測った値で決める。

| ID | 内容 | 目標値 |
| --- | --- | --- |
| N-1 | ログインしてからタイムラインの最初の 20 件が表示されるまで | 3 秒以内 |
| N-2 | タイムラインの 20 件を返す API の応答（「フォロー中」「すべて」とも） | 1 秒以内 |
| N-3 | 本のページ（本の情報・平均評価・最初の 20 件のレビュー）が表示されるまで | 2 秒以内 |
| N-4 | 参考になった・フォロー・読書ステータスを押してから画面に反映されるまで | 0.5 秒以内 |
| N-5 | 写真 4 枚（合計 20MB）のレビューを投稿してから、本のページに出るまで | 10 秒以内 |
| N-6 | 書籍検索の結果が表示されるまで。Google Books API の応答時間を含む | 3 秒以内 |

### 11.2 可用性・データ保全

| ID | 内容 |
| --- | --- |
| N-7 | 稼働時間は AWS の稼働に従う。本アプリ独自の稼働率の目標は設けない。費用を抑えるために止めている間（P-6）は使えない |
| N-8 | Google Books API が使えないときは、書籍検索だけが使えなくなり、すでに保存した本のページ・レビュー・本棚は使える。検索の画面には「本の検索がいまできません」と出す |
| N-9 | データベースは 1 日 1 回自動でバックアップし、7 日分を残す（RDS の自動バックアップ）。ただし AWS が無料プランの間は、無料プランの上限のため 1 日分だけを残す。失われる可能性があるのは、最後のバックアップ以降の変更のみ |
| N-10 | S3 の写真は、レビューを削除したとき、編集で写真を外したとき、書いた人が退会したときにだけ消す。それ以外で消えないようにする |

### 11.3 セキュリティ

| ID | 内容 |
| --- | --- |
| N-11 | 公開時の通信はすべて HTTPS（暗号化）で行う |
| N-12 | ログインしていない状態では、データの読み書きを一切できない |
| N-13 | 各利用者は、自分のレビュー・写真・コメント・参考になった・フォロー・読書ステータス・プロフィールだけを変更・削除でき、自分のアカウントだけを退会できる。画面だけでなくサーバー側でも確かめる |
| N-14 | パスワードは元に戻せない形（BCrypt）で保存する。そのままの形では保存もログ出力もしない |
| N-15 | 同じユーザー ID で 5 回続けてログインに失敗したら、15 分間そのユーザー ID でログインできないようにする |
| N-16 | 写真を置く S3 は外部から直接読めないようにし、画面には有効期限 15 分の署名付き URL で渡す |
| N-17 | レビュー・コメント・プロフィールの文字と、Google Books API から取った本の情報は、HTML として解釈させずにそのまま表示する（他人の画面でスクリプトを動かさせない） |
| N-18 | データベースのパスワード、JWT の署名に使う秘密の値、AWS の認証情報、Google Books API の API キーは、ソースコードとリポジトリに置かない。API キーは画面（ブラウザ）にも渡さない |
| N-19 | ログインの状態は JWT で持ち、JavaScript から読めない Cookie（HttpOnly）に入れる。JWT の有効期限は 15 分と短くし、ログインしたままにするためには別のリフレッシュトークン（有効期限 14 日）を使う。ログアウトしたら、リフレッシュトークンをサーバー側で無効にする |

### 11.4 使いやすさ

| ID | 内容 |
| --- | --- |
| N-20 | 画面の文字はすべて日本語とする（本の情報は 2.2 のとおり API が返したまま） |
| N-21 | 文字と背景の色の明るさの比（コントラスト比）を 4.5:1 以上とする |
| N-22 | 取り消せない操作（レビュー・コメントの削除、退会）の前には、必ず確認ダイアログを出す。退会では、パスワードも入れ直してもらう |

## 12. リスクと対策

| No | リスク | 影響 | 対策 |
| --- | --- | --- | --- |
| R-1 | AWS の費用が想定を超える | 費用が発生し続ける | 公開は検収のときだけ行い、使わない間は止める（P-6）。AWS Budgets で月 10,000 円を超えそうなときにメールを受け取る |
| R-2 | 誰でも登録できるため、不適切なレビュー・写真が載る | ほかの利用者が不快になる、著作権を侵害する | 公開する URL を知り合いにだけ伝える。見つけた場合は作成者がデータベースと S3 から削除する |
| R-3 | パスワードの総当たりで、ほかの人のアカウントに入られる | なりすましてレビューを書かれる | ログイン失敗の回数制限（N-15）とパスワードの条件（FN-01） |
| R-4 | S3 の写真が外部から見られる | 投稿した写真が漏れる | バケットを非公開にし、署名付き URL で渡す（N-16） |
| R-5 | データベースの障害・操作の誤りでデータが消える | レビューなどが失われる | RDS の自動バックアップから戻す（N-9） |
| R-6 | Google Books API が止まる、1 日の回数の上限に達する、仕様が変わる | 本を探せず、新しい本のレビューを書けない | 保存済みの本は使えるようにする（N-8、P-4）。上限は 1 日 1,000 回とみなし（P-3）、同じ検索を繰り返したときは前の結果を使って呼ぶ回数を減らす（やり方は基本設計書で決める）。上限に達したときは N-8 と同じく検索だけを止める。公開の前に、Google Cloud のコンソールで実際の上限を確かめる |
| R-7 | 日本の本の一部が Google Books API にない、または情報が欠けている（表紙・ISBN がないなど） | その本を記録できない、表紙が出ない | 表紙がない本は「表紙なし」の枠を出す。見つからない本は登録できないことを操作マニュアルに書く。手入力は作らない（U-3 で決めた） |
| R-8 | Google Books API の API キーが漏れる | 回数の上限を他人に使われる | キーはサーバーだけが持ち（N-18）、Google Cloud でこの API だけに使えるよう制限する。漏れたらキーを作り直す |
| R-9 | ブラウザの仕様変更で動きが変わる | 一部の機能が動かなくなる | 保守期間中は不具合として対応する（15 章） |

### 13.1 進め方

| 手順 | 内容 | 担当 |

### 13.2 期間

検収期間は、納品した日の翌日から 7 日間とする。延長する場合は、作成者と承認者の両者で合意する。

### 13.3 不具合の重さと扱い

| ランク | 内容 | 例 | 扱い |
| --- | --- | --- | --- |
| A | データが失われる・漏れる、または主な機能が使えない | レビューが消える、他人のレビューを削除できる、ログインできない | 修正して再テストするまで合格としない |
| B | 機能は使えるが、本書の内容と動きが違う | メッセージが表示されない、星 0 でレビューを書ける | 修正して再テストするまで合格としない |
| C | 使うのに支障がない見た目の問題 | 文字が 1px ずれる | 修正するかどうか、いつ修正するかを両者で決める |

### 13.4 合格の条件

1. テスト仕様書のすべての項目が全 7 環境で合格している。ただし、作成者・検収者の手元に実機がない環境（macOS・iOS・Android）は、代わりの環境（WebKit・端末のエミュレーション）での合格で代えてよい
2. ランク A・B の不具合が残っていない
3. 14 章の納品物がすべてそろっている

## 16. 変更管理

承認後に要件を変える場合は、次の手順で行う。

| 手順 | 内容 | 担当 |
| --- | --- | --- |
| 1 | 変更したい内容と理由を、GitHub の Issue に「変更依頼」として書く | 依頼する人（どちらでもよい） |
| 2 | 変更による影響（作業時間、納期、ほかの機能への影響、AWS の費用）を調べ、Issue に書く | 作成者 |
| 3 | 変更するかどうかを決める | 承認者 |
| 4 | 変更する場合は本書・詳細文書（1.3）・機能定義書を書き直し、版数を上げて改訂履歴に記録し、再度承認を受ける | 作成者・承認者 |

版数の上げ方：承認までは 0.1 ずつ上げ（例：0.1 → 0.2）、承認したら 1.0 とする。承認後は、文言の修正のみは 0.1 上げる（例：1.0 → 1.1）。機能の追加・削除は 1.0 上げる（例：1.1 → 2.0）。

詳細文書を変えた場合は、その文書の版数を上げて改訂履歴に記録する。あわせて本書の版数も上げ、改訂履歴に「どの詳細文書を何版にしたか」を記録する。承認は本書で行うため、本書の版数が要件定義書全体の版数となる。
