## 1. 結論

**公開先（AWS）で測った結果、N-1〜N-6 はすべて目標以内で、合格である**（2026-11-07）。30 人が同時に使っているときも、目立って遅くならなかった。

| 要件 | 内容 | 目標 | 公開先の P95（画面の幅・負荷の有無のうち最も遅いもの） | 判定 |
| --- | --- | --- | --- | --- |
| N-1 | ログインしてからタイムラインの最初の 20 件が表示されるまで | 3 秒以内 | 1.19 秒（スマートフォン・負荷なし） | 合格 |
| N-2 | タイムラインの 20 件を返す API の応答 | 1 秒以内 | API 0.36 秒。画面で押してから 20 件が出るまで 0.67 秒（スマートフォン・30 人） | 合格 |
| N-3 | 本のページが表示されるまで | 2 秒以内 | 1.48 秒（スマートフォン・負荷なし） | 合格 |
| N-4 | 参考になった・フォロー・読書ステータスを押してから画面に反映されるまで | 0.5 秒以内 | 表示 0.10 秒。応答で確定 0.31 秒（スマートフォン・30 人） | 合格 |
| N-5 | 写真 4 枚（合計 20MB）のレビューを投稿してから、本のページに出るまで | 10 秒以内 | 7.63 秒（パソコン） | 合格 |
| N-6 | 書籍検索の結果が表示されるまで | 3 秒以内 | 2.05 秒（パソコン） | 合格 |

P95 は、同じ操作を繰り返し測った値を小さい順に並べて 95% の位置の値である（20 回なら遅い方から 2 番目）。

## 3. 気をつけること

- **ランナーから公開先までの通信を含む**：API の P50 が 120ms ほどなのは、ランナー（日本の外）から東京の公開先までの往復を含むためと考えられる。日本から使うと速くなる見込みで、手元で測った値（手元の DB 宛で 8〜25ms）とは比べられない
- **N-6 はばらつきが大きい**：P50 は 0.30 秒、P95 は 2.05 秒、最大は 4.76 秒。使い回しのない検索は Google Books API の応答に左右される。20 回のうち目標の 3 秒を超えたのは最大の 1 回だけで、判定の P95 は目標以内
- **読書ステータスの最大値**：負荷ありのスマートフォンで、応答の確定の最大が 1.06 秒の回があった（P95 は 0.31 秒）。判定は P95 なので合格
- **写真の表示**：投稿してから写真まで出るのは P95 で 24.3 秒（参考の項目。合否の対象外）。N-5 はカードが出るまでで、写真は下り 10Mbps の条件で 20MB を読むのに時間がかかる
