## 1. 方針

要件定義書 13.1 のとおり、要件 ID ごとに 1 件以上のテストを用意する。テストはできるだけ自動にし、Pull Request ごとに GitHub Actions で動かす（N-28）。

| 種類 | 何を確かめるか | 置き場所 | いつ動かすか |
| --- | --- | --- | --- |
| API | API の入力・出力・権限・データ（Controller・Service・Repository の単体と、API を通したもの）。DB は Testcontainers の PostgreSQL、S3 は MinIO、Google Books API は MockRestServiceServer | backend/src/test/java | Pull Request ごと（`mvnw verify`） |
| 画面 | 画面の部品と画面ごとの動き。API は偽物にする | frontend/src/\*\*/\*.test.ts(x) | Pull Request ごと（`npm test`） |
| E2E | 本物の API・DB につなぎ、ブラウザで利用者の操作の流れを確かめる。Google Books API だけ偽物にする。アクセシビリティ（axe）と 375px の横幅も | frontend/e2e | Pull Request ごと（CI は Edge。ほかのブラウザは 3 章） |
| 性能 | 要件定義書 11.1（N-1〜N-6）の時間を P95 で判定する | perf/k6、frontend/perf | 任意のとき（基本設計書 2.4）。公開先では開発計画書 2-8 で測る |
| テスト以外 | 設定・文書を見る、公開先で確かめる | | 検収のとき（開発計画書 2-8） |

## 2. 要件 ID とテストの対応

### 2.1 テストに要件 ID・観点の ID を書く決まり

テストを書くときは、確かめる要件 ID（A・B・RV・PH・H・C・F・ST・T・BK・PF・G・M・N・BR。docs/README.md の ID の一覧）と、機能定義書 10 章のテストの観点の ID（TC-機能の番号-連番。例：TC-03-1）を、次のどこかに書く。ID を書くのは、そのテストが実際に確かめているものだけにする。

| 書く場所 | 例 | どのテストに付くか |
| --- | --- | --- |
| テストの名前 | `it('M-6：ユーザー ID かパスワードが違うときは…')`、`test('…（TC-03-1・TC-03-2）')` | そのテスト |
| テストの直前のコメント | `// BR-6`（JUnit では `@Test` の上でもよい） | 次のテスト |
| テストの中 | `// M-11` | そのテスト |
| 区切りのコメント | `// ---- 登録（A-1〜A-4）----` | 次の区切りまでのテスト |
| describe・@Nested のクラス名 | `describe('ログイン（G-1）', …)` | 次の区切りまでのテスト |

`A-1〜A-4`・`TC-03-1〜3` のように範囲でも書ける。

### 2.2 対応表

[要件 ID とテストの対応表](requirement-coverage.md) は、`node scripts/requirement-coverage.mjs` がテストのファイルを読んで作る。手で直さない。

- 対応表は 1 章が要件 ID、2 章がテストの観点（機能定義書 10 章）。どちらも、確かめるテストを種類（API・画面・E2E・性能）ごとに並べる
- テストのない要件 ID・観点があるとき、または対応表を作り直していないときは、`node scripts/requirement-coverage.mjs --check` が失敗する。GitHub Actions でも Pull Request ごとに動かす
- テストではなく、設定・文書を見て確かめる要件 ID（N-7・N-9・N-11・N-20・N-25〜N-28）は、確かめ方を対応表に書く（スクリプトの中の一覧で決める）
- 要件 ID の種類のうち、P（前提）・R（リスク）・U（未決事項）・Q（設計で見つけた不足）・SG（セキュリティグループ）は、テストの対象にしない。SG はインフラ設計書と Terraform の検査（tflint）で確かめる

## 3. 環境ごとの結果

### 3.1 対応環境と、代わりに確かめた環境

要件定義書 3.2 の 7 つの環境のうち、作成者のパソコン（Windows 11）にあるのは Windows のブラウザだけである。ほかの環境は次の代わりのブラウザで E2E を流し、実機は 4 章の手順で確かめる（要件定義書 13.4 の 1）。

| No | 対応環境 | 代わりに確かめた環境（Playwright の project） | 画面の幅 | 流すテスト |
| --- | --- | --- | --- | --- |
| 1 | Windows 11・Google Chrome | Chrome 156（chrome） | 1280px | E2E すべて |
| 2 | Windows 11・Microsoft Edge | Edge 156（pc・mobile。CI も） | 1280px・375px | E2E すべて（375px は主な流れと全画面） |
| 3 | Windows 11・Mozilla Firefox | Playwright の Firefox（firefox） | 1280px | E2E すべて |
| 4 | macOS・Safari | Playwright の WebKit（webkit。Safari と同じエンジン） | 1280px | E2E すべて |
| 5 | macOS・Google Chrome | No.1 と同じ（Chrome は OS で動きが変わらない） | | |
| 6 | iOS・Safari | WebKit で iPhone 15 の大きさ・User-Agent・タッチ（iphone） | 393px | 主な流れと全画面 |
| 7 | Android・Google Chrome | Chrome 156 で Pixel 7 の大きさ・User-Agent・タッチ（android） | 412px | 主な流れと全画面 |

流し方：README「画面を通したテスト」のとおりに 3 つのサーバー（DB・API・画面）を起動し、frontend で `E2E_BROWSERS=all npx playwright test`（PowerShell では `$env:E2E_BROWSERS='all'; npx playwright test`）。Firefox と WebKit は先に `npx playwright install firefox webkit` で入れる。この流し方のときだけ、落ちたテストを 1 回やり直す。やり直して通ったものは「flaky」と出るので、結果に書く。

## 4. 手動で確かめる項目

### 4.1 実機

検収のとき（開発計画書 2-8）に公開先の URL を実機で開いて、次を確かめる。ユーザーは 2 人作る（2 台目の端末か、パソコンのブラウザを使う）。

| No | 操作 | 確かめること | 関係する ID |
| --- | --- | --- | --- |
| 1 | ユーザー登録する。ユーザー ID を 2 文字にして「登録する」 | 入力欄の下に M-2 が出る。正しく直すと登録できて G-3 に移る | A-1〜A-4、M-2 |
| 2 | ログアウトして、パスワードを間違えてログインする | フォームの上に M-6 が出る。正しいパスワードでログインできる | A-5、A-6、A-9、M-6 |
| 3 | ブラウザを閉じて開き直す | ログインしたまま G-3 が出る | A-8、TC-01-5 |
| 4 | ヘッダーの検索欄に書名を入れて探し、本を選ぶ。ISBN でも探す | 結果が出て、選ぶと G-5 が開く。ISBN では 1 冊に決まる | B-1〜B-3、B-5 |
| 5 | G-5 で「読みたい」を押す。押し直す | すぐに表示が変わり、本棚に出る。押し直すと外れる | ST-1〜ST-3 |
| 6 | 端末の写真（スマートフォンはカメラロール）から 4 枚選んでレビューを投稿する | 星・感想・写真 4 枚がカードに出る。写真を押すと大きく出て、左右に切り替え・閉じられる | RV-1〜RV-3、PH-1、PH-2、PH-7 |
| 7 | もう 1 人のユーザーでフォローし、タイムラインの「フォロー中」を開く | 相手のレビューが出る | F-1、T-1 |
| 8 | 「参考になった」を押す。もう一度押す | すぐに数が変わり、もう一度で戻る | H-1、H-2 |
| 9 | レビューの詳細画面で、コメントを書いて「コメントする」 | 書いた文字が一覧の下に出る | C-1 |
| 10 | 自分のレビューを「…」から削除する。写真つきのレビューで試す | 確認ダイアログに M-19 が出て、「削除」で消える | N-10、N-22、M-19 |
| 11 | どの画面も、縦に持って（スマートフォン）・画面の拡大率を 150% にして（パソコン）見る | 横にスクロールせず、文字が切れない。本の情報のほかは文字がすべて日本語 | N-20、N-23、要件定義書 3.2 の拡大率 |

| 13 | G-9 の「退会する」でパスワードを入れて退会する | M-11 が出て G-1 に移る。同じユーザー ID でログインできない | A-10〜A-12、N-22 |
